# Apply Utopia Configuration Guide

## Config Directory

| File | Purpose |
|------|---------|
| `config/demo.yaml` | Demo personas, jobs, tenant requests, admin/employer logins |
| `config/trust-registry.yaml` | Trust registries (education institutions, employers) |
| `config/credential-analysis.yaml` | Default credential analysis workflow (credential types, extraction, matching). Admin can override via Admin UI. |

## Configuration File

The application uses a `config.json` file located at `frontend/public/config.json` for runtime configuration.

### Configuration Options

```json
{
  "app": {
    "name": "Apply Utopia",
    "shortName": "Apply Utopia",
    "description": "Discover jobs and manage your career with Apply Utopia",
    "domain": "https://marketplace.example.com",
    "themeColor": "#003366",
    "backgroundColor": "#F5F5F5"
  },
  "api": {
    "baseUrl": "/api"
  },
  "features": {
    "offlineMode": true,
    "pushNotifications": false
  }
}
```

### Configuration Fields

#### App Settings
- **name**: Full application name (used in PWA manifest)
- **shortName**: Short name for home screen (12 chars or less recommended)
- **description**: App description for PWA manifest
- **domain**: Your production domain (e.g., `https://marketplace.yourdomain.com`)
- **themeColor**: Primary theme color (hex format)
- **backgroundColor**: Background color for splash screen

#### API Settings
- **baseUrl**: Base URL for API calls (default: `/api`)

#### Feature Flags
- **offlineMode**: Enable offline functionality via service worker
- **pushNotifications**: Enable push notifications (requires setup)

## Deployment Configuration

### Development
The default `config.json` is suitable for local development.

### Production
Before deploying to production:

1. Update the `domain` field with your production URL
2. Update `api.baseUrl` if your API is on a different domain
3. Adjust feature flags as needed

### Environment-Specific Configs

You can maintain different config files for different environments:

```bash
# Development
cp config.dev.json frontend/public/config.json

# Staging
cp config.staging.json frontend/public/config.json

# Production
cp config.prod.json frontend/public/config.json
```

## PWA Configuration

The PWA is configured in `frontend/vite.config.ts`. Key settings:

- **Icons**: Place PWA icons in `frontend/public/img/digicred/`
- **Service Worker**: Automatically generated by Vite PWA plugin
- **Caching**: API and image caching configured for offline support

### Required Icons

For optimal PWA support, provide icons in these sizes:
- 192x192 (required)
- 512x512 (required)
- 180x180 (iOS)

Place icons in `frontend/public/img/digicred/` and update the manifest in `vite.config.ts`.

## Testing PWA

### Local Testing
```bash
cd frontend
npm run build
npm run preview
```

Then open Chrome DevTools > Application > Manifest to verify PWA configuration.

### Production Testing
1. Deploy to HTTPS domain (required for PWA)
2. Open site in Chrome
3. Check for "Install" prompt
4. Test offline functionality by disabling network in DevTools

## Service Worker

The service worker provides:
- **Offline support**: Cached assets work without network
- **API caching**: Network-first strategy for API calls
- **Image caching**: Cache-first for external images
- **Auto-updates**: New versions automatically update

### Cache Strategy
- **API calls**: NetworkFirst (24-hour cache)
- **Images**: CacheFirst (30-day cache)
- **Static assets**: Precached during install

## Troubleshooting

### PWA not installing
- Ensure site is served over HTTPS
- Check manifest.json is accessible
- Verify icons are correct size and format

### Offline mode not working
- Check service worker is registered (DevTools > Application > Service Workers)
- Verify `offlineMode` is `true` in config.json
- Clear cache and reload

### Config changes not reflecting
- Hard refresh (Ctrl+Shift+R / Cmd+Shift+R)
- Clear service worker cache
- Rebuild application

## Environment Variables

| Variable | Description |
|----------|-------------|
| `PORT` | Backend server port (default: 5174) |
| `DATABASE_TYPE` | Database type: `postgres` or `sqlite` (default: sqlite) |
| `DATABASE_URL` | PostgreSQL connection URL (required when DATABASE_TYPE=postgres) |
| `DATABASE_PATH` | SQLite database file path (default: ./data/marketplace.db) |
| `CORS_ORIGIN` | Comma-separated allowed origins (empty = allow all, dev only) |
| `MARKETPLACE_ADMIN_URI` | Marketplace Admin (ACA-Py) base URL, e.g. `http://localhost:8031` |
| `MARKETPLACE_ADMIN_API_KEY` | API key for Marketplace Admin API authentication |
| `MARKETPLACE_TENANCY_URI` | Marketplace Tenancy (ACA-Py multitenant) base URL, e.g. `http://localhost:8032`. Used for marketplace plugin (create invitation, analyze transcript). |
| `MARKETPLACE_TENANCY_API_KEY` | API key for Marketplace Tenancy API authentication |

## Security Notes

- **Never commit secrets** – Use `config.local.json` (gitignored) for local overrides with credentials
- Use environment variables for API keys and tokens
- Set `CORS_ORIGIN` env var in production to restrict API origins
- Validate all config values on load
